## Overview

Остаток этапа 1 из `docs/development-plan.md` после [плана 02](20261105-02-v0-review-core.md): строки «`setup`/`init` для двух пилотных агентов», «`doctor` и минимум закрытого контура», «`ctx`: импорт через агента» и «Guide-тексты и промпты стадий v0». Пилотные агенты — Claude Code и Qwen Code; производные (обёртка-песочница, форк) описываются наследованием `base:` в конфиге.

```
plait setup [--agent A] [--scope user|project] [--dry-run] [--uninstall]   # разработчик
plait init [--dry-run]                                                      # тимлид, один раз на репо
plait doctor [--net]                                                        # окружение и закрытый контур
plait ctx <KEY>                                                             # инструкция агенту получить задачу
plait guide <stage>                                                         # подробная инструкция стадии
```

После плана разработчик ставит plait в своего агента одной командой, вызывает `/plait-review`, а агент дальше ведёт себя по `plait next` и `plait guide`.

Не входит: headless-запуск агентов и проверка read-only (этап 2), skills для Codex, Gemini CLI и pi (начало этапа 2), allow-list endpoint'ов и system-оверлей промптов (этап 6), Jira REST (этап 3).

## Solution Overview

**Агент — это данные, а не код.** Агент описывается дескриптором: команда, пути skills, контекст-файл, формат запрета команд, признаки выключенной телеметрии, переменная endpoint'а модели. Встроенные дескрипторы вшиты (`internal/agent/builtin/*.yaml`), свои задаются в конфиге `agents.<name>` тем же набором полей. Код есть только там, где агенты различаются по-настоящему: форматы файлов настроек — небольшой реестр «писателей» по имени (`claude-settings`, `none`, …). Новый агент с уже известным форматом — один YAML-файл без правки Go-кода; новый формат — один писатель. Codex, Gemini CLI и pi на этапе 2 добавляются так же. `Run` для headless — этап 2, тот же дескриптор получит секцию запуска.

**Наследование `base:`** — частный случай: дескриптор из конфига берёт поля у другого (встроенного или своего) и переопределяет заданные.

**plait владеет только своими файлами.** Каждый установленный skill помечен во frontmatter (`plait-managed: true`, `plait-version`). Файл без метки не перезаписывается и не удаляется — это конфликт, о нём сообщается. В общих файлах (`AGENTS.md`, `settings.json`) plait меняет только свою секцию или свои правила, остальное сохраняется байт в байт, где формат позволяет.

**Сеть только по флагу.** `doctor` без `--net` не ходит в сеть: читает окружение и файлы. `--net` проверяет endpoint'ы через общий транспорт `internal/netx` — тот же, что позже возьмут forge и Jira.

## Technical Details

Дескриптор агента (`internal/agent`, схема `plait-agent/v1`, одинакова для `builtin/*.yaml` и `agents.<name>` в конфиге):

```yaml
name: claude
display: Claude Code
cmd: claude
version_args: [--version]
skill_dirs: { user: ~/.claude/skills, project: .claude/skills }
context_file: CLAUDE.md
skill_frontmatter: { disable-model-invocation: true }   # добавляется к stage-skills
permissions:
  writer: claude-settings          # имя из реестра писателей; none — запрет не поддерживается
  user: ~/.claude/settings.json
  project: .claude/settings.json
  deny: [plait approve, plait reject]
  source: <URL документации формата>
telemetry_off:                     # любое условие из списка — ok; json без equals — любое истинное значение
  - env: DISABLE_TELEMETRY
  - env: CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC
  - json: { file: ~/.claude/settings.json, path: env.DISABLE_TELEMETRY }
  - json: { file: ~/.qwen/settings.json, path: privacy.usageStatisticsEnabled, equals: false }   # пример
model_endpoint_env: ANTHROPIC_BASE_URL
session_env: CLAUDECODE            # ➕ агент ставит её в 1 в своём shell; имя агента в аудите
```

- Слои конфига сливают `agents.<name>` так же: карты по ключам, списки заменяются; env и флаги их не задают. Имена писателей — `agent.Writers()`, у каждого должна быть реализация в установщике.
- `base:` — взять дескриптор по имени и переопределить заданные поля (вложенные карты сливаются, списки заменяются). Неизвестный `base`, цикл, неизвестный `writer`, отсутствие обязательных полей (`cmd`, `skill_dirs`, `context_file`) после слияния — `Invalid` `config_invalid` с именем агента.
- Реестр писателей запрета: интерфейс `PermissionWriter { Plan(path, rules) ([]Op, error); Remove(path, rules) ([]Op, error) }`; в v0 — `claude-settings`, `qwen-settings` (➕ тот же `permissions.deny` в JSON, правило `Bash(<cmd> *)`) и `none`.
- Правила запрета задаются в дескрипторе как абстрактные команды (`plait approve`, `plait reject`); писатель переводит их в синтаксис агента.
- Пилотные агенты v0 — встроенные `claude` и `qwen`; `setup` без `--agent` берёт всех встроенных и своих, которые нашлись в `PATH`.

Встроенные дескрипторы v0:

| | Claude Code | Qwen Code |
| --- | --- | --- |
| `cmd` | `claude` | `qwen` |
| skills user / project | `~/.claude/skills/` / `.claude/skills/` | `~/.qwen/skills/` / `.qwen/skills/` |
| контекст-файл | `CLAUDE.md` | `QWEN.md` |
| запрет команд | `permissions.deny` в `~/.claude/settings.json` / `.claude/settings.json`: `Bash(plait approve:*)`, `Bash(plait reject:*)` | ➕ `permissions.deny` в `~/.qwen/settings.json` / `.qwen/settings.json`: `Bash(plait approve *)`, `Bash(plait reject *)`; источник — `permissions.source` в `builtin/qwen.yaml` |
| телеметрия выключена | `DISABLE_TELEMETRY=1` или `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` в env или в `env` из `settings.json` | `privacy.usageStatisticsEnabled: false` в `~/.qwen/settings.json` (`QWEN_USAGE_STATISTICS_ENABLED=false` условием `env` не выразить) |
| endpoint модели | `ANTHROPIC_BASE_URL` | `OPENAI_BASE_URL` |

- `Detect`: `exec.LookPath(cmd)`, затем `<cmd> <version_args>` с таймаутом 5 с; нет в `PATH` — не установлен, не ошибка.
- Конфиг `agents.<name>` с тем же именем, что встроенный, переопределяет его поля.
- Skills, `init`, `doctor` и `setup` перебирают реестр дескрипторов и не содержат имён конкретных агентов: тест ищет `"claude"`/`"qwen"` в Go-коде вне `internal/agent/builtin` и тестов.

Skills (`internal/skills`, `go:embed`, `text/template`):

- `plait` — общий: что такое run, «сначала `plait next --json`», контракт (JSON, exit codes, `fix`), `plait guide <stage>`.
- `plait-review` — сторона автора: `plait ctx`/`ctx save`, проверки через `check save`, `review export`, попросить разработчика открыть новую сессию с пакетом и сохранить ответ, `review import`, `review report`. Явно: пакет в этой сессии не ревьюить.
- `plait-mr` — `mr describe` с резюме изменений.
- Frontmatter: `name`, узкий `description` («используй, когда пользователь явно попросил /plait-…»), `plait-managed: true`, `plait-version`; для Claude Code у `plait-review`/`plait-mr` — `disable-model-invocation: true`. 20–40 строк каждый.

`plait guide <stage>`: `ctx`, `review`, `fix`, `mr`, `reviewer` (как вести свежую сессию по пакету — для разработчика, который её открывает). Тексты — `internal/skills/guides/*.md`. Неизвестная стадия — `Invalid` со списком стадий. `next` добавляет поле `guide` с командой для текущего шага.

`setup`:

- По умолчанию — все обнаруженные пилотные агенты, `--scope user`; `--agent` — один, в том числе производный из конфига.
- Ставит skills, запрет команд, затем выполняет проверки `doctor` без сети и печатает их.
- Повтор с той же версией — `changed:false`; другая версия — обновляет файлы с меткой; файл без метки на месте skill — пропуск с `conflict` в ответе и exit 4 в конце, если конфликты были.
- `--dry-run` печатает план операций (`create | update | skip | conflict` с путём) и ничего не пишет. `--uninstall` удаляет только файлы с меткой и только свои правила запрета.
- `settings.json`: читается как JSON, добавляются только отсутствующие правила, остальные ключи и порядок массивов сохраняются; файл с невалидным JSON не трогается — `Invalid` с путём и `fix`.

`init`:

- Только в git-репо; создаёт `.plait/config.yaml` из шаблона с комментариями (если нет), project-skills для обоих пилотных агентов, секцию в `AGENTS.md` между `<!-- plait:begin -->` и `<!-- plait:end -->` (создаёт файл, если нет; обновляет только секцию), строку `@AGENTS.md` в `CLAUDE.md` и `QWEN.md`, если её там нет, строки `/.plait/*`, `!/.plait/config.yaml` и `!/.plait/rules.md` в `.gitignore`, если их нет.
- Повтор — `changed:false`; `--dry-run` — как у `setup`.

`doctor` (`internal/doctor`):

- Проверка = `{name, status: ok|warn|fail, detail, fix}`; exit 0 без `fail`, иначе 4.
- Без сети: версия plait; для каждого агента — установлен ли, версия, skills на месте и их `plait-version` совпадает с бинарём, правила запрета, телеметрия выключена, endpoint модели (показать значение и хост); репо — `.plait/` доступна на запись, конфиг читается, `.gitignore` скрывает `.plait/runs`; контур — `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`, CA из `network.ca_file` или `SSL_CERT_FILE` читается и содержит хотя бы один сертификат.
- `--net`: для каждого endpoint модели и `network.endpoints[]` — HTTPS-запрос с таймаутом 5 с через `internal/netx`; ошибка сертификата — `fail` с `fix` про `network.ca_file`; недоступность — `fail` с адресом прокси, если он есть.
- `internal/netx.Transport(cfg)`: `http.ProxyFromEnvironment`, системный пул + `network.ca_file`/`SSL_CERT_FILE`, TLS ≥ 1.2. Тест-ограничение: `net/http` импортируют только `internal/netx` и `internal/doctor` (проверка импортов через `go/parser` по дереву исходников).

`ctx <KEY>`:

- `KEY` — `^[A-Z][A-Z0-9]*-[0-9]+$` (➕ `run.ValidKey`, как у `run new`), иначе `Invalid`. ➕ Ключ run берётся из префикса id (`run.KeyOf`), иначе из `task.Key`; run без ключа принимает любой.
- Без текущего run — `Invalid` с `fix: plait run new <slug> --key <KEY>`. Ключ run другой — `Invalid` `key_mismatch`.
- Ответ как у `next`: `do` — получить задачу `KEY` инструментом `jira.mcp_tool` (если задан) или любым доступным агенту доступом к Jira и передать summary, описание, критерии приёмки и комментарии Markdown'ом в `plait ctx save KEY --source jira`; если Jira недоступна — попросить разработчика описать задачу и сохранить с `--source local`. Конфиг `jira.mode` (только `mcp` в v0), `jira.mcp_tool`.
