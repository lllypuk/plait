## Solution Overview

**Находка переживает прогоны.** У каждой находки ключ `R<n>-<id>` (номер ревью и id из ответа). Открытые находки прошлого ревью переносятся в пакет следующего: ревьюер в свежей сессии ставит по каждой вердикт `fixed | still_open | not_checked`. Он видит прежние находки, но не рассуждения автора: это вывод ревьюера, а не автора.

**Статус решает вердикт, а не исчезновение строки.** Привязка находки к новому снимку считается git'ом: `git diff -U0 <старый снимок> <новый>` по файлу находки (с учётом переименования). Строка вне изменённых участков сдвигается, внутри — участок изменён, файл удалён — привязки нет. «Исправление подтверждено» ставит только вердикт `fixed`; изменённый или пропавший участок без вердикта — повод перепроверить, а не «исправлено».

**Проверки не запускаются, а захватываются.** Агент сам запускает тесты и линтер и сохраняет результат через `plait check save`. Результат привязан к дереву рабочей копии на момент сохранения; в пакет снимка он идёт как свежий, только если дерево совпадает с деревом снимка.

**Неполное покрытие видно.** К метке `criteria`/`diff_only` добавляется список пробелов: дифф урезан, файлы исключены, ожидаемых проверок нет или они упали, ревьюер не смог проверить часть критериев.

**Аудит без содержимого.** Журнал хранит пути, хеши и решения, но не текст файлов. Файлы из `audit.deny_globs` в пакет не попадают совсем: ни дифф, ни содержимое правил.

## Technical Details

Конфиг (`internal/config/defaults.yaml`, новые ключи):

```yaml
review:
  max_diff_bytes: 524288   # больше — файлы диффа выкидываются целиком, от самых крупных
  checks: []               # имена ожидаемых проверок, например [test, lint]
audit:
  deny_globs: [".env", ".env.*", "**/*.pem", "**/*.key", "**/id_rsa*", "**/secrets/**", "**/*.p12", "**/*.keystore"]
mr:
  template: ""             # путь в репозитории к своему text/template; пусто — встроенный
```

`int` в слоях конфига: env и флаги принимают десятичную строку; ошибка разбора — `Invalid` `config_invalid`, как для остальных типов.

`check save`:

- `plait check save <name> --exit-code N [--file F | stdin]`; `name` — `^[a-z0-9][a-z0-9_-]*$`.
- Пишет `.plait/runs/<id>/checks/<name>.json` (схема `plait-check/v1`): `name`, `exit_code`, `tree` (текущее дерево рабочей копии тем же способом, что снимок), `saved_at`, `output_sha256`, `output_tail` — последние 200 строк, не больше 16 KiB, после редактирования секретов.
- Редактирование секретов: значение в строках вида `<имя>=<значение>` / `<имя>: <значение>`, где имя содержит `token|secret|password|passwd|api_key|apikey|private_key` (без учёта регистра), заменяется на `[redacted]`.
- Повтор с тем же выводом, кодом и деревом — `changed:false`. Шаг run не меняет.

Пакет `review export` (дополнения к `package.md`):

- Раздел «Previous findings» для ревью n>1: открытые находки прошлого ревью (статусы `open`, `region_changed`, `outdated`) с ключом, серьёзностью, заголовком, обоснованием и местом в **новом** снимке (или пометкой «участок изменён» / «файл удалён»). Инструкция: дать вердикт по каждому ключу в `previous[]`, не дублировать их в `findings`.
- Раздел «Checks»: для каждой проверки из `review.checks` и каждой сохранённой — имя, код выхода, свежесть (`fresh` — дерево = дерево снимка, иначе `stale`), `output_tail` свежих. Ожидаемая, но не сохранённая — `missing`.
- Файлы из `audit.deny_globs` (сопоставление по пути от корня, `path.Match` по сегментам и `**`): дифф заменяется строкой `excluded by audit.deny_globs`, такие же файлы правил не читаются.
- Дифф больше `review.max_diff_bytes`: файлы выкидываются целиком, начиная с самого большого вклада, до укладывания в лимит; их пути перечислены в пакете.
- `coverage_gaps` (в пакете и `state.json` снимка): `diff_truncated`, `files_excluded`, `checks_missing`, `checks_failed`, `checks_stale` — по списку путей/имён.
- Отпечаток пакета в сообщении коммита снимка учитывает новые разделы, как и раньше.

`review-findings/v1`, необязательные поля:

- `previous[]`: `{"key": "R1-auth-1", "verdict": "fixed|still_open|not_checked", "note": "..."}`; `note` обязателен для `fixed` и `still_open`.
- `unchecked_criteria[]`: критерии из задачи, которые ревьюер не смог проверить по диффу, дословно.
- Импорт: ключ `previous`, которого нет в пакете, — `Invalid` `unknown_previous`; ключ из пакета без вердикта считается `not_checked`; `unchecked_criteria` непусто — пробел `criteria_unchecked`.

Привязка и статусы (`internal/review/compare.go`, `internal/vcs`):

- `vcs.MapLine(ctx, oldCommit, newCommit, file, line) (newFile string, newLine int, state)`, `state` ∈ `unchanged | changed | gone`; `line == 0` (находка про весь файл): `changed`, если файл изменился, иначе `unchanged`. Переименование — через `git diff -M`.
- Статус находки в ревью n:
  - своя находка ревью n — `new`;
  - прежняя, вердикт `fixed` — `fix_confirmed`, дальше не переносится;
  - прежняя, вердикт `still_open` — `open`, место — привязка в новом снимке;
  - прежняя без вердикта или `not_checked`: `changed` — `region_changed`; `gone` — `outdated`; `unchanged` — `open`.
- Своя находка ревью n, совпавшая с прежней открытой по файлу, строке после привязки и заголовку без учёта регистра, не дублируется: прежняя получает `open`.
- Результат сравнения пишется в `.plait/runs/<id>/findings-<n>.json` (схема `plait-findings/v1`: все находки с ключом, статусом, местом в снимке n и историей статусов) атомарно при импорте; отчёт и `mr describe` читают его, а не пересчитывают.

`review report`: группировка по статусу, затем по серьёзности; метка покрытия с пробелами («проверено по критериям задачи, неполно: дифф урезан (2 файла)»); `coverage_gaps` и счётчики по статусам в JSON. `next` на шаге `reported`: есть `open`/`region_changed`/`outdated` с серьёзностью `blocker` или `major` — исправить и `review export`; иначе — `mr describe`.

`mr describe`:

- Требует импортированное ревью: иначе `Invalid` `no_review` с `fix: plait review export`.
- Рабочая копия изменилась после последнего ревьюированного снимка — `Invalid` `snapshot_stale` с `fix` (экспорт и ревью заново); `--allow-stale` строит описание с явной пометкой в теле.
- Заголовок: `<KEY>: <summary>` при ключе задачи, иначе `<summary>`; `summary` — заголовок `task.md` без префикса ключа.
- Тело (встроенный `templates/mr.md.tmpl`, английский; `mr.template` — свой шаблон с теми же данными, путь только внутри репо): резюме из `--summary-file`/stdin, если передано; задача и критерии — каждый критерий с пометкой `flagged`, если на него ссылается открытая находка, иначе без пометки (plait не утверждает, что критерий выполнен); ревью — метка покрытия с пробелами, снимок, счётчики статусов, открытые `blocker`/`major` списком; проверки — имя, код, `fresh`/`stale`/`missing`; строка `Generated by plait <version>`, метка `ai-assisted`.
- Пишет `.plait/runs/<id>/mr.md`; JSON: `title`, `body`, `path`, `stale`. Повтор с теми же данными — `changed:false`. Шаг `described` (`next`: описание готово, создание MR — вручную).

Аудит (`internal/audit`):

- `.plait/runs/<id>/audit.jsonl`, одна строка на каждую команду, которая меняет run или читает его для пакета: `ts`, `plait_version`, `cmd` (имя подкоманды без значений флагов), `run`, `step_from`, `step_to`, `agent`, `snapshot`, `package_sha256`, `context` (`[{path, sha256}]`: `task.md`, файлы правил, файлы диффа), `excluded` (`[{path, reason}]`), `answer_sha256`, `error` (`code`) при отказе.
- `agent`: `PLAIT_AGENT`, иначе по окружению (`CLAUDECODE=1` → `claude`), иначе `unknown`.
- Запись — `O_APPEND` под тем же `flock` `.plait/lock`; строка не больше 64 KiB, иначе списки урезаются с полем `truncated: true`. Содержимое файлов, вывод проверок и ответы в журнал не пишутся.
