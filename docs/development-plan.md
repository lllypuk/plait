# plait — план разработки

5 ноября 2026. Основа — `docs/plait-brief.md`, разделы «Первая версия» и «Roadmap».

## Как читать оценки

- Шкала Фибоначчи для отдельных работ; суммы этапов — просто суммы.
- Якорь: 2 SP — cobra-команда `version` с вшиванием версии через `-ldflags` и тестом. 8 SP ≈ неделя одного разработчика с агентом — гипотеза до фактической скорости первых пакетов.
- Оценки включают тесты и документацию своей работы; отдельного этапа тестирования нет.
- Этапы 0–1 оценены по работам. Этапы 2–6 — диапазон размера эпика: переоцениваются перед стартом, по результатам предыдущего этапа. Складывать диапазоны в обещанную дату нельзя.
- SP — это не календарь. Пилот ждёт подходящих задач и людей; это время планируется отдельно.
- Остановка или упрощение после замера — допустимый исход, а не недовыполненный план.

## 1. v0: польза с одним агентом — 79 SP

Результат для разработчика: в своём агенте он доводит задачу до MR с ревью по критериям задачи, а после смены сессии видит, что исправлено и что ждёт решения.

| Контракт вывода и run: JSON/TTY, exit codes, `next --json`, `state.json`, `run new/resume/list`, идемпотентность, восстановление после прерывания | 8 |
| `setup`/`init` для двух пилотных агентов: embed skills, наследование `base:`, deny-правила, секция `AGENTS.md`, сохранность пользовательских файлов, повторный запуск, `--dry-run`/`--uninstall`. Готово — [план 03](plans/completed/20261105-03-v0-install.md). | 8 |

| Guide-тексты и промпты стадий v0. Готово — [план 03](plans/completed/20261105-03-v0-install.md). | 5 |

Review суммарно 21 SP — перед реализацией разбит на три работы выше. Runner `verify` не входит, только захват результатов.

**Контрольная точка — сквозной срез.** Внутри 79 SP, не отдельный этап. Первым собирается цепочка: локальное описание задачи → снимок диффа → ручная свежая сессия → импорт → понятный отчёт. На ней сразу начинаются наблюдения пилота, не дожидаясь полного `setup`/`doctor` и сравнения прогонов; готовым v0 срез не считается. Он проверяет, что сценарий работает и сколько стоит ручная передача. Гипотезу об экономии на повторных проверках оцениваем позже, когда готово сравнение прогонов. Отрицательные наблюдения на срезе — повод остановиться или упростить, а не достраивать все 79.

Срез готов — [план 01](plans/completed/20261105-01-v0-slice.md); дальше наблюдения пилота на нём.

## 2. Второе мнение — 34–55 SP

Результат: ревью второй моделью из сессии основного агента одной командой, находки сведены в один список. Диапазон уже включает оба headless-адаптера, перенесённые из v0.

- Skills для остальных трёх агентов — отдельной поставкой в начале этапа: поддержка нового агента с одним ревьюером не ждёт worker и cross-agent review. Headless для них — experimental.
- Headless-адаптеры двух пилотных агентов: нормализация результата, невалидный JSON, отмена и таймаут, проверка read-only. С ними появляются автоматическая свежая сессия и техническая гарантия read-only ревьюера; в ручном режиме v0 её нет.
- `review --with` и сведённый отчёт: без повторов, с серьёзностью и основанием, видимые разногласия, одиночные важные находки не теряются.
- `plait worker` на одно задание для песочниц, где запуск агентов запрещён.
- Замер 2: свежая сессия той же модели против второй модели.

## 3. Маршруты и MR — 34–55 SP

Результат: тимлид задаёт короткий и плановый маршруты, агент ведёт задачу от анализа до draft MR.

- `routes` в конфиге, статус `not_required`, исключения с подтверждением человека, пересчёт маршрута.
- `analyze`, `plan new/check/save`, `plan_review`, публикация плана в `docs/plans`.
- Гейт `approve`/`reject` через TTY.
- `mr create` по разрешению `forge.create_mr`: GitLab, затем GitHub.
- `ctx` в режиме `rest`.

## 4. Реализация и цикл — 34–55 SP

Результат: агент реализует одобренный план по шагам и проходит цикл ревью → исправления до готового MR.

- `implement --step` с подтверждением шагов, `implement` целиком.
- `fix` с лимитом итераций и детектором стагнации.
- Runner `verify` по командам из конфига.
- Worktree, отмена и возобновление.
- Политика автономии по путям.

## 5. Общение агентов — 55–89 SP

Несколько независимых подсистем; при старте этапа берутся по спросу, не целиком.

- `debate` и `council` для `plan_review` и `review`.
- Встроенный MCP-сервер (`ask_agent`, `send_message`/`read_inbox`) и CLI-дубль.
- Очередь общего назначения.
- `say`/`tail`, findings board, leases.

## 6. Enterprise — 34–55 SP + CI-гейт 13–21 SP

- System-конфиг, оверлей промптов, хуки стадий, allow-list endpoint'ов.
- PAN-сканер, `stats`.
- Инструкция по корпоративному зеркалу.
- CI-гейт для MR — отдельно: проверяет, что ревью относится к актуальному диффу и действующим правилам, и доверие к артефактам; это сложнее проверки наличия run.

## Не оцениваем

GoReleaser и публичные релизы, ACP-адаптер, контейнерный режим, A2A — при появлении спроса.
